# Project State

## 1. Product Purpose

MDI provides a durable materials-science workspace in which users manage source data, request validated analyses, inspect authoritative scientific results, and receive grounded interpretations and reports.

## 2. Current V0 Scope

Authenticated projects and datasets; immutable scientific object versions and provenance; validated Analysis Plans and Tool Registry execution; asynchronous Research Turn, Plan, Job, Result, Interpretation, and Report workflows; deterministic scientific adapters; PostgreSQL durability, Redis/RQ execution, MinIO object storage, and browser recovery from durable state.

Research also supports scientific work without a pre-uploaded material: knowledge and method dialogue, versioned element reference plots, bounded parameter calculations, direct text-data plots and ideal crystal models. Seven registered tools cover periodic tables, element-property comparisons, unit conversion, function curves, formula composition, inline XY data and ideal lattices. The single composer distinguishes platform references, user parameters/text and exact sample sources; it never selects a project material implicitly. Execution remains asynchronous through validated registry tools and controlled adapters, with traceable results and existing report/export paths. The broader scientific-display and source-free work in the complete goal's section 50 remains active.

## 3. Explicit Non-goals

Arbitrary LLM execution, hidden chain-of-thought display, browser-owned scientific authority, development mocks replacing core stores, and M6/F15 execution under the superseded roadmap.

## 4. Current Architecture

Next.js talks to FastAPI. FastAPI persists identity and workflow state in PostgreSQL, stores payloads/artifacts in MinIO, and enqueues asynchronous work through Redis/RQ. One local multi-queue worker consumes the active logical queues; ownership, leases, fencing, and idempotent publication remain database-authoritative.

AnalysisPlan 0.4 adds explicit PROJECT execution without a fabricated Dataset or sample. Version/hash-bound platform references and exact resolved user parameters are persisted with their input origin; inline tables retain the original supplied text. Existing material plans and cross-dataset AnalysisPlan 0.3 remain supported. Results, facts, interpretation and reports validate the same saved inputs, tool calls and artifacts before presenting them.

## 5. Core Modules

`apps/api` owns API/application/persistence/Research orchestration; `apps/web` owns the UI; `packages` owns schemas, registries, adapters, parsers, and artifacts; `services/workers` owns RQ execution; `services/llm` owns bounded provider integration.
