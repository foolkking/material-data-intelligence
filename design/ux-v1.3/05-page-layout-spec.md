# Page Layout Specification

## Landing

- Desktop: max content 1320px, two columns; outcome copy at left and real workbench scene at right.
- Hero uses 64-72px visual breathing room, not a rounded hero card. At least the next workflow band is visible at 1440x900.
- Below the workflow band, use full-width editorial sections to explain the Project research boundary and the scientific result reading order. These are unframed bands with one real workbench/publication surface, not feature-card grids.
- Mobile: scene follows copy; browser scroll; no split layout.
- CTA: `进入 Console` primary; `查看研究流程` secondary.

## Console and Projects

- Console lead: continue a Project before offering a project list.
- Recent Projects: three dense equal text regions divided by hairlines, not cards. Each shows real research wording, update time, and a meaningful next link.
- Projects: same information grammar as Console but expands to the collection and archive.

## Project Overview

- Header has a research-purpose statement and concise Project facts.
- Two columns below: research activity (date, event, scientific context, state) and Project data inventory.
- Data links open Project Data or Quick Preview. No default raw Dataset/Profile identifiers.

## Data

- Workbench area height: viewport minus 56px GlobalBar and 44px ProjectNav.
- Navigator `264px` at wide desktop; Viewer consumes remaining width; Inspector `344px` when open.
- Table: 52px viewer toolbar, 40px default rows/headers, sticky property headers, readable 12px units shown inside headers, selected row maps to Inspector.
- Toolbar contains title, scientific context, viewer controls and owned page action only. A permanent details command and nested “预览” action are removed; Inspector opens from a scientific selection.
- Structure/trajectory: a large canvas with only object title/context overlay and lower factual footer. Do not split this into 3 cards.
- XRD/electronic: plot surface with labels, axes/units, succinct note, optional Inspector selection.
- Volumetric: scientific scalar color field; product color is not used as an aesthetic gradient.
- Archive: `detected content` list only, with explicit capability status. Unsupported: scientific explanation and recovery path.

## Research

- Desktop: Conversation `36%`; splitter can adjust `30-45%`; remaining width is Dynamic Workbench.
- Workbench header `48px`; Activity `224px`; result region is scrollable and owns main canvas/document.
- Conversation holds durable exchange, compact human answer, suggestions when applicable, and composer anchored below content.
- Plan lives in workbench as `分析方案`; it presents data selection, scientific steps, expected outputs and limitations. Machine contract is hidden.
- Running Activity is always visible without a tab switch. A completed artifact appears in the result region while a later observed step can remain active.

## Reports

- Reports page contains only current Run Reports. State and run context scan in rows.
- Reader width 820-900px. Result prose uses editorial/scientific reading rhythm; Figure is never presented as a dashboard widget.
